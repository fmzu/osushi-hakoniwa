# すしづめ

「おすしのはこにわ」の追加章。満員電車を題材にしたスライドパズル。クリアするごとに乗客が寿司になる。

- ページ: `sushizume.html`（本編 `index.html` の「🚃 すしづめ」から行ける。すしづめ側に「← はこにわへ」がある）
- 実装: `src/puzzle/`（ルールの正は `src/puzzle/core.ts`）、面づくりの道具は `tools/sushizume/`

## 解決する課題

1. **誰の・どんな課題か**: 本編は放置して眺める遊びなので、「自分で頭を使って遊ぶ」手応えがない。短く区切れて、手を動かして解ける遊びがほしい
2. **なぜ本編に混ぜないか**: 本編は「寿司が来て帰る」眺める遊び。パズルをクリアした寿司を同じ箱庭に溜めようとすると、「寿司が溜まるのか帰るのか」で仕組みがぶつかる。雰囲気も一段ダークなので、「追加章」として分けて見どころにする
3. **導入前後の変化**: 前: 眺めて図鑑を埋めるだけ / 後: スマホ片手で1面数分のパズルを解く遊びが増え、クリアの気持ちよさ（鯛が寿司に変わる）が加わる
4. **放置すると何が困るか**: 試作のまま手元の単体ファイルに留まり、面やルールの検証（最短手数・ヒント）が再現できず、後から手を入れられなくなる

## 位置づけ

- 本編の遊び方（来店・退店・呼び鈴・図鑑）には手を入れない。保存も別（本編 `osushi-zukan-v2`、すしづめ `osushi-sushizume-v1`）
- 数人（5章）で終わる短編。図鑑埋めではない
- パズルとストーリーは切り離す。盤面はただの盤面として見て、「クリア後に何の寿司になるか」「名前付きの乗客が盤上のどのコマか」とは対応させない

## パズルのルール

箱入り娘型。盤は W×H の格子で、コマは矩形。1手＝コマを上下左右に1マス滑らせる。

- **ゴール**: 主人公（宇宙人）がターゲット（鯛）に辺で接したら**即クリア**（斜めは接していない）。ターゲットは動かない。話しかける場面はクリア後のストーリー側で描く
- コマは空きマスにしか動けない（跳び越え・入れ替えなし。例外は納豆のみ）
- 同じ文字が隣接している駒は横長・縦長・塊として1つの駒
- **制限手数**: 最短手数の約1.3倍（`ceil(最短 × 1.3)`）。超えると「次の駅に着いてしまった」で失敗。やり直せる

### コマの種類

| 種類         | 文字盤     | 動く | 性質                                                                                                                                                                                                                   |
| ------------ | ---------- | ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 主人公       | `H`        | ○    | 運ぶ本体。見た目は宇宙人                                                                                                                                                                                               |
| ターゲット   | `T`        | ×    | 固定。見た目は鯛（盤の上でピチピチ跳ねる）。クリアすると鯛の握りに変わる                                                                                                                                               |
| 乗客（寿司） | `a`〜`z`   | ○    | ただの壁。どかして道を作る                                                                                                                                                                                             |
| 納豆         | `W`        | ○    | **動かすのに2手かかる**。1手目で拾い集め（盤は変わらない）、2手目で動く。他のコマを動かすと解除される。動くとき、行き先にいる**1×1のコマと入れ替われる**（長いコマ・2×2・ターゲット・わさびとは入れ替われない）        |
| わさび       | `A` か数字 | ×    | 固定。**主人公が新たに隣に入ったときだけ**「ツーン！」で手数+1（移動1＋罰1＝合計2手）。2つの間に入ると+2。他のコマが隣に入っても増えない。隣に居続けるあいだは再発しない。納豆との入れ替えで主人公が動いた場合も数える |

- 納豆は1面に1つまで（例外役だから光る。全コマが割り込めると、空きの資源管理が消える）
- 「空きを無視して動ける」能力は納豆の入れ替え以外に足さない
- わさびは1面に複数置ける。文字盤では `A` か数字（`1` `2`…）で書く

### 補助機能と金／銀

- **一手戻す**: 手数も戻る
- **ヒント**: 次の一手のコマを光らせ、矢印で向きを示す。面ごとに事前計算した正解手順の上にいればそれを即答し、外れていればブラウザ内のソルバーで探す（どの局面からでも出ること）。探索は Web Worker（`src/puzzle/hintWorker.ts`）で回し、考えているあいだも画面を止めない。探索中に盤を動かしたらその結果は捨て、ヒントの使用にも数えない。状態数の上限で打ち切ったときは「無理」とは言わず、ヒントの使用にも数えない
- **はじめから**
- **次の面へ**: クリア後に出る
- **金／銀**: 「一手戻す」「ヒント」を使わずにクリア＝金、使ったら銀。各面に保存し、金は銀で上書きされない。面選択に🥇🥈の印を出す

## 面（5章×3面＝15面）

章＝寿司にする乗客。章が進むほど難しい。面の元データは `tools/sushizume/levels.src.json`（章・呼び名・番号・文字盤）、ゲームが読む `src/puzzle/levels.json` はそこから計算した生成物（最短手数・制限・正解手順入り）。

| 章  | 乗客       | 面数 | 最短手数 |
| --- | ---------- | ---- | -------- |
| 1   | Aさん      | 3    | 10〜12   |
| 2   | おっさん   | 3    | 13〜17   |
| 3   | 主婦       | 3    | 18〜20   |
| 4   | 女子高生   | 3    | 23〜25   |
| 5   | イクラの子 | 3    | 23〜28   |

- 難易度はヒントがある前提（普通には解きにくいが、ヒントで必ず進める）
- 面は山登り生成（`tools/sushizume` の `gen`）で作り、「最短手数が章の目安内」「納豆を普通の乗客にすると2手以上増え、最短手順で納豆を使う」「わさびをただの壁にすると2手以上減る」ものを採用。一部は手作り
- すべての面は、ソルバーで解の存在と最短手数を確認してから採用する（`go test` と `vp test run` が15面すべてで再確認する）

## 見た目

- コマは基本すべて寿司（主人公・鯛だけ例外）。形でネタが決まる
  - 1×1: 握り（マグロ・タマゴ）。納豆は本編と同じ軍艦。ふだんは軍艦が左にずれて右側へ崩れ落ちる「こぼれ納豆」
  - 横長 2×1: アナゴ一本・カニの押し寿司（切れ目入り）・サバの棒寿司
  - 縦長 1×2: 恵方巻きだけ。具（定番・海鮮）と外側（海苔・とろろ昆布）で種類を変える
  - 2×2: 太巻き
  - わさび: シャリの上に緑の山盛り。普通の握りには緑のネタを使わない（わさびと紛れるため）
- 主人公は宇宙人（怖い目）。盤のマスはスマホで1マス50px前後なので、コマの絵は16px以上
- 演出: 「ツーン！ +1」のポップ、クリア時に鯛が鯛の握りに変わって「スシッ」、鯛のピチピチ
- 本編から借りる絵（マグロ・タマゴ・納豆・シャリ）は `src/sprites.ts` / `src/species.ts` を再利用し、パズル専用の絵は `src/puzzle/sprites.ts` に置く

## 操作

- コマの上でスワイプすると、その向きに1マス動く（マウスのドラッグでも可）
- スマホ幅（400px）で遊べる前提。1画面に収め、盤面が主役、上に手数、下に操作

## データ永続化

- `localStorage` キー `osushi-sushizume-v1`: 各面の金／銀と、読んだ物語（`{ "medals": { "1-1": "gold" }, "read": { "1-start": true, "1-end": true } }`）。`read` が無い旧データも読める
- 本編のキー `osushi-zukan-v2` には触れない
- 保存できない環境（プライベートブラウジング等）でも落ちず、保存しないだけで遊べる

## 技術構成

- `src/puzzle/core.ts`: ルール・ソルバー・文字盤の読み込み（描画なし）。ルールの正
- `src/puzzle/levels.ts` / `levels.json`: 面データ
- `src/puzzle/sprites.ts`, `looks.ts`, `drawBoard.ts`, `screen.ts`, `main.ts`: 描画・入力・画面
- `src/puzzle/progress.ts`: 進行の保存（金銀・既読）
- `src/puzzle/story.ts`: 物語の本文（正）。`needsStart` / `needsEnd` / `betweenLine` / `readableParts` / `markRead` / `isRead` が「いつ何を出すか」の判断（DOM に触れない）、`showLines` / `showWord` / `showMenu` / `openOverlay` / `closeOverlay` が暗い全画面の表示
- `sushizume.html`: Vite のマルチページ（`vite.config.ts` の `build.rollupOptions.input`）
- `tools/sushizume/`（Go）: 面の元データから最短手数・制限・正解手順を計算し `levels.json` を書き出す。ゲーム本体には含まれない。`core.ts` とルールが一致していることを `go test` が守る

## 物語の見せ方

本文は `src/puzzle/story.ts` が正（ここには書かない）。1章ごとに「始まり」「終わり」「一行」を持つ。

- **表示**: 暗い全画面。タップ／Enter／Space で1行ずつ出す。空行は読ませず間だけ空ける。最後の行だけアクセント色。右下に「▼」、右上の隅に小さな「とばす」。`prefers-reduced-motion` ではフェードもにじみも無し
- **章の始まり**: 章の1面目に入るとき、その章の始まりをまだ読んでいなければ自動で出す（初回の起動時を含む）。読み終える（またはとばす）と暗がりから盤面がにじみ出て、盤面の下に目標「宇宙人を、鯛の隣へ」が出る。2回目以降は自動では出さない（面選択から直接入る遊び方を邪魔しない）
- **面と面の間**: 1面目・2面目のクリア後に「次の面へ」を押すと、暗い画面に一言（1面目のあと「まだ、遠い。」、2面目のあと「あと、少し。」。全章共通）→ タップで次の面（盤面はにじみ出る）
- **章の終わり**: 3面目をクリアすると、鯛が寿司に変わった盤面を約1.5秒見せてからゆっくり暗転 → 章の終わり → 一行だけの画面（「◯章　おしまい」）。初めてクリアしたときだけ自動で出す
- **読み返し**: 読んだことのある始まり・終わりが1つでもあると、面選択の隣に「ものがたり」が出る。読んだものだけを選んで読み返せる（未読の章は出さない）
- **既読**: 読み終えた（またはとばした）時点で章ごとの始まり・終わりを保存する。途中でページを閉じたら未読のまま

## 箱庭の住人

章の3面目をクリア（金か銀）すると、その章の寿司が本編の箱庭に住みつく。起動時に1匹ずつ出る。実装は `src/residents/`。

- **どの章で何が**: 1章まぐろ／2章あなご／3章かんぴょう巻き／4章太巻き／5章いくら。かんぴょう巻き・太巻きは物語専用の種（ランダム来店しない）
- **目印なし**: 見た目は普通の寿司と同じ（大きさも16×16）。タップして一行が出て初めて気づく
- **タップ**: 普通の寿司と同じ（♡・なかよし度）に加えて、頭上の吹き出しに `story.ts` の `line` を約2.6秒出す。連打すると延長する
- **帰らない・図鑑外**: 退店の対象外。図鑑（見かけた・なかよし）には数えず、物語専用の種はなかよし度も保存しない
- すしづめの保存データは読むだけで、箱庭からは書き込まない

## テスト観点

- `vp test run`: ルール単体（移動・納豆・わさび・勝敗・戻す）、15面すべての正解手順の再生と最短手数・制限の検証、ヒント、進行の保存
- `go test`（`tools/sushizume`、CI は `.github/workflows/sushizume-tools.yml`）: Go 側のルール単体、`levels.json` の15面で Go の最短手数 = `best`、`levels.src.json` と `levels.json` の一致
- 手動: スマホ幅で表示・スワイプで1面クリア・リロード後も金が残る・本編からリンクで行ける

## 撤回した案（再提案しない）

- ターゲットを扉まで運ぶ（主人公とターゲットの両方を操作して視点が曖昧になる）
- ターゲットが自動で扉へ進む（スライドパズルではなく追いかけっこになる）
- 扉に寄る乗客・隙間を埋める乗客（最短手数を増やせず、邪魔の強さを証明できなかった）
- 途中で盤が変わる降りる人・乗ってくる人、面の途中の車両移動（場合分けが爆発し、逆算作業になる）
- ランダム要素（解ける面が作れない）
- 名前付きの寿司に好きな場所や振る舞いを持たせる（そこまでの個性はつけない。物語はテキスト側で語る）
