# tools/sushizume

「すしづめ」（満員電車のスライドパズル）の**面を作り直すときだけ使う道具**です。ゲーム本体（`vp build` の成果物）には含まれません。

- 面の元データ: `levels.src.json`（人が編集する。章・名前・番号・文字盤だけ）
- ゲームが読む生成物: `../../src/puzzle/levels.json`（`export` が書き出す。手で編集しない）

最短手数・制限手数・正解手順（ヒントに使う）は元データから計算して生成物に入れます。

## ルールの正は `src/puzzle/core.ts`

Go のソルバー（`rules.go`）は、`src/puzzle/core.ts` のルールを高速に解くための実装です。**ルールの正は `core.ts`** で、変えたら Go も同じに直してください。ずれると、ゲームの最短手数と生成物の `best` が食い違います（`go test` が落ちるようにしてあります）。

ルール一覧:

- 盤は W×H。駒は矩形で、空きマスにだけ1マスずつ滑る（盤の外・他の駒には動けない）
- 文字盤の記法: `H`=主人公 `T`=ターゲット `W`=納豆 `A` か数字=わさび `.`=空き、その他の文字=乗客。同じ文字が隣接していれば1つの矩形駒
- ゴール: 主人公がターゲットに辺で接したら即クリア（斜めは接していない）。ターゲットとわさびは動かない
- 1手のコストは1
- 納豆（`W`）: 動かすのに2手かかる。1手目は「拾い集める」（盤は変わらない。向きは問わない）、2手目で動く。他の駒を動かすと拾い集めた状態は解除される。動くときは、行き先にいる**1×1の駒と入れ替われる**（長い駒・2×2・ターゲット・わさびとは入れ替われない）
- わさび: 主人公が動いた結果、**新たに**わさびの隣になるたびに、その1つにつきコスト+1（「ツーン！」）。2つの間に入れば+2。他の駒がわさびの隣に入っても増えない。隣に居続けるあいだは再発しない。納豆との入れ替えで主人公が動いた場合も、主人公が動いたものとして数える
- 制限手数 = `ceil(最短手数 × 1.3)`（`export` の `-ratio` で変更できる）

## 使い方

`tools/sushizume/` で実行します（Go 1.24）。

### export — 面を作り直す

```sh
# levels.src.json を編集したら
go run . export
# -ratio 1.5 で制限の倍率、-src / -out で入出力先を変えられる
```

`src/puzzle/levels.json` が書き換わります。元データを変えずに実行して差分が出なければ、生成物は最新です。書き出した JSON は `vp check`（pre-commit）の整形を通しても変わらない形にしてあります。

### solve — 盤を解く

```sh
go run . solve 'h.dpjT/nrfckk/tofgie/mbbaiH/m.qqsl'
```

行を `/` でつないだ文字盤を渡すと、最短手数（`cost`）・正解手順（`sol`）・探索した状態数・納豆を使うか・わさびをただの壁にしたときの最短（`wall`）を JSON で1行出します。

### gen — 面を山登りで生成する

```sh
# 5×6の盤に、納豆1つ・わさび1つ・太巻き1つ。最短24〜30手を目標に10分探す
go run . gen -ch 4 -w 6 -h 5 -lo 24 -hi 30 -natto 1 -was 1 -big 1 -secs 600 -workers 4
```

条件を満たした面を、1行1JSONで標準出力に流します。`rows` は `levels.src.json` にそのまま貼れます。条件は「最短手数が `-lo` 以上」「納豆を普通の乗客にすると2手以上増え、最短手順で納豆を使う」「わさびを壁にすると2手以上減る」です（納豆・わさびの数を0にすると、その条件は見ません）。

## チェック

```sh
gofmt -l .        # 何も出ないこと
go vet ./...
go test ./...
```

`go test` は次を確かめます。

- 小さな盤でのルール単体（`src/puzzle/core.test.ts` と同じ観点）
- `src/puzzle/levels.json` の15面すべてで、Go の最短手数が `best` と一致し、`sol` を再生するとクリアできる
- `levels.src.json` から計算し直した結果が `levels.json` と一致する（`export` のやり忘れの検出）

CI は `.github/workflows/sushizume-tools.yml` で、`tools/sushizume/**`・`src/puzzle/levels.json`・`src/puzzle/core.ts` が変わったときに上の3つを走らせます。

TS 側（`src/puzzle/*.test.ts`）は PR ごとに `.github/workflows/ci.yml` で走ります。`core.ts` のルールを変えて15面の最短手数が変わると、TS のテスト（`levels.test.ts`）が `levels.json` の `best` と食い違って落ちるので、Go 側も直して `go run . export` してください。
